# XCLing UI 全量重构设计

## 背景

XCLing 当前使用传统 WPF + MVVM 界面，页面功能完整，但主窗口、页面布局和共享控件仍偏紧凑、保守，图标与动画不足。此次重构参考 yetone/magpie 的桌面工具信息架构与克制的工具型视觉语言，目标是在不改变现有策略业务、RPC 协议、托盘生命周期和 Win7 兼容目标的前提下，形成统一、完善、可维护的桌面 UI。

## 目标

- 全量升级主窗口、导航、页面布局和共享设计系统。
- 统一浅色/深色主题的颜色、间距、字体、圆角、边框、状态语义和控件风格。
- 通过少量必要组件复用页面标题、状态徽章、提示条、信息卡片、空状态和动画。
- 加入增强型但克制的原生 WPF 动画：页面转场、导航指示器、卡片错峰、列表变更、Toast、按钮状态和加载状态。
- 保留所有现有 ViewModel、命令、RPC、业务校验、确认流程、托盘行为和数据持久化语义。
- 通过构建、单元测试和 UI 冒烟验证确保改造可回归。

## 非目标

- 不重写 Go 核心或 JSON-RPC 协议。
- 不引入 WebView2、第三方 WPF UI 框架或额外运行时依赖。
- 不改变白名单、黑名单、保护模式、恢复原状、临时解锁和审计记录的业务规则。
- 不改变关闭窗口隐藏托盘、托盘退出和单实例唤起语义。
- 不为动画引入持续循环、复杂模糊或依赖现代系统 API 的效果。

## 设计方案

### 主窗口

主窗口继续采用左侧导航 + 右侧 ContentControl 页面映射 + 底部状态栏的壳层。左侧增加品牌区、分组导航、统一线性图标和底部关于入口；右侧增加页面标题/说明/操作区，页面内容使用更明显的卡片层级。默认尺寸调整到约 1180x760，最小尺寸不低于 880x580，以适应信息卡片和表格。现有导航 key、启动页环境变量、activity-operations 深链和 About 特殊入口保持兼容。

### 设计令牌

在现有 `Themes/Light.xaml`、`Themes/Dark.xaml` 和 `Themes/Shared.xaml` 上扩展：

- Surface0-Surface5 背景层级。
- Text0-Text3 文字层级。
- Border、Primary、Success、Warning、Danger、Info 及其 Hover/Pressed/Soft 变体。
- 统一 8px 间距体系、圆角、控件高度、卡片阴影和动画时长资源。
- 所有主题颜色继续通过 DynamicResource 使用，保持 ThemeManager 运行时切换能力。
- 增加概览、规则、记录、设置、关于、刷新、添加、删除、搜索、警告等 Lucide Geometry 图标，维持现有许可证和 Win7 字体兼容策略。

### 必要组件

只抽取跨页面重复且具有稳定职责的组件/样式：

- 页面标题区：标题、说明和操作区。
- 状态徽章：保护中、未启用、临时解锁、异常等状态。
- 信息卡片：指标、状态和简要描述。
- 提示条：错误、警告、过期和信息通知。
- 空状态：无规则、无记录、无扫描结果。
- 动画内容容器和动画列表模板。

优先通过共享 Style、ControlTemplate、DataTemplate 和附加属性实现，只有需要独立行为时才创建自定义控件，避免复杂依赖属性层。

### 页面设计

- **概览**：顶部状态 Hero 卡片，突出当前保护状态和主要动作；下方为模式、规则数、备份、权限等信息卡片；最近操作和恢复区域保持明确的危险操作隔离。
- **白名单**：顶部说明和模式状态；添加路径区域卡片化；自定义规则、待启用路径、默认信任目录、已安装程序扫描分区清晰；路径采用等宽字体并保留完整 Tooltip。
- **黑名单**：顶部状态与刷新；厂商预设、本机扫描、当前规则、添加规则分区卡片化；危险删除和批量操作突出但不抢占主操作。
- **运行记录**：状态概览与刷新；拦截记录/操作记录 Tab 统一样式；表格强化表头、行状态、空状态、加载状态和审计不可用提示。
- **设置**：按外观、通用、兼容性分区；设置项采用清晰的行式布局，开关和选择控件统一，主题切换即时生效。
- **关于**：品牌信息、版本/更新、作者链接、捐助和法律说明分区；保留外链与捐助命令行为。

### 动画

使用 WPF 原生 Storyboard、DoubleAnimation、ThicknessAnimation、ColorAnimation 和 TranslateTransform/ScaleTransform：

- 页面进入：透明度 0→1 + X 方向轻微位移。
- 导航：激活指示条和背景平滑过渡。
- 卡片：首次呈现按短延迟错峰淡入/上移。
- 列表：新增、移除使用淡入淡出与轻微位移；不破坏虚拟化表格。
- Toast：右下角滑入、停留、淡出，手动关闭可中断。
- 按钮/卡片：Hover、Pressed、禁用和状态颜色过渡。
- 加载：刷新按钮轻量旋转或加载态反馈，完成后停止。

动画时长采用短时资源（约 120–280ms），不使用持续闪烁；尊重低性能设备，避免复杂阴影和高成本渲染。动画触发不改变命令执行、Busy 状态和错误处理。

## 数据流与兼容性

ViewModel 和页面实例缓存机制不变。MainViewModel 继续通过 CurrentPage 和 DataTemplate 映射页面，导航时调用 `OnActivatedAsync`。Toast、PendingPaths、AppServices、ThemeManager、Settings 和确认窗口接口保持兼容。所有现有绑定、AncestorType 命令绑定、AutomationProperties、键盘焦点和危险操作确认必须保留。

主题字典仍保持主题字典在 Shared.xaml 之前的合并顺序，ThemeManager 仍能依据 Light/Dark Source 找到并替换画笔。新增资源必须同步 `XCLing.Wpf.csproj` 的 Resource 项；不得移动现有 logo、捐助二维码和许可证资源而造成打包路径变化。

## 错误处理

布局和样式修改不得吞掉或替代页面自身错误呈现。页面加载异常继续由页面 ViewModel 呈现；异步命令仍使用现有 RelayCommand 与页面 Busy/Loading 状态。动画异常不得影响命令结果，必要时由视觉层触发后自动结束。外链、更新、捐助、核心连接和托盘行为沿用现有错误处理。

## 验证

1. `git diff --check` 检查空白和合并冲突。
2. `go test -count=1 ./...`、`go vet ./...`、`go build ./...` 验证 Go 核心。
3. 使用 .NET SDK 构建 WPF 项目，确认 net48 资源、XAML 和绑定编译通过。
4. 运行 `scripts/verify-wpf-ui.ps1`，检查页面、主题、窗口尺寸、绑定和关键交互。
5. 至少验证浅色/深色切换、窗口缩放、导航转场、Toast、规则列表、扫描/表格、危险确认、托盘隐藏与重新打开。
6. 检查 Win7 兼容代码路径未依赖新系统专有控件或 API。

## 实施顺序

1. 建立分支并保存本设计。
2. 扩展 Light/Dark/Shared 设计系统、图标和动画资源。
3. 重构主窗口和导航壳层。
4. 按概览、白名单、黑名单、运行记录、设置、关于顺序迁移页面布局。
5. 增加必要的共享动画/视觉组件并接入 Toast、页面和列表。
6. 更新资源打包项，构建并执行测试与 UI 冒烟验证。
7. 清理临时文件，检查差异范围，等待用户审核后再提交代码。
